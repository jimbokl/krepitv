# Design Specification

## Context

После обновления главной страницы различаются шапки статического генератора и React, а карточки моделей сохраняют устаревшую круглую кнопку. На карточке кронштейна технические цифры идут раньше объяснения результата.

## Goal

Сделать системную, неброскую полировку типографики, первого экрана и элементов взаимодействия без смены визуального направления KREPI TV.

## Non-goals

Новые страницы, новые визуальные активы, изменение данных о товарах, логики Rust/WASM, партнёрских ссылок и аналитики.

## Inputs

DESIGN.md, web/AGENTS.md, существующие токены Tailwind, мобильные и десктопные снимки исходных страниц.

## Constraints

Русский язык, статический GitHub Pages, минимум 320 px, WCAG 2.2 AA, существующая архитектура Rust SSR + React, безопасные утверждения о совместимости.

## States

Обязательные состояния default/loading/empty/error/success/disabled/focus сохраняются в мастере подбора; фокус отдельно проверяется визуально. У страниц каталога нет асинхронного состояния, поэтому их состояние по умолчанию проверяется отдельно.

## Acceptance tests

Статическая и React-шапки показывают одну марку и одинаковую навигационную иерархию. Основные CTA используют один прямоугольный стиль. Карточка кронштейна на мобильном объясняет следующий шаг перед сводкой параметров. Все ссылки и summary доступны с клавиатуры, имеют видимый фокус. Нет переполнения на 320/768/1440 px и при 200% тексте. Сборка, тесты и production smoke проходят.

## Allowed files

crates/sitegen/src/main.rs, web/src/components/SiteHeader.jsx, web/src/components/CatalogBrandGroups.jsx, web/src/pages/MountPage.jsx, web/src/styles.css, DESIGN.md и этот design-harness run.

## Verification commands

Полная сборка npm run build; визуальная проверка через npm run qa:screenshot на 320/768/1440 и ключевых состояниях; проверка UI и GitHub Pages после релиза.

## Sources and claims

Новых проверяемых технических утверждений нет. Формулировки только объясняют существующие паспортные данные и ограничения; бренд и токены из DESIGN.md.

## Asset contract

Новых растровых активов нет; существующие иллюстрации сохраняются без изменений. Точный текст создаётся кодом, не моделью генерации изображений.

## Review and rollback

Независимый ревьюер проверяет снимки, исходный diff и границы утверждений. Откат — возврат одного релизного коммита без изменения данных каталога.
