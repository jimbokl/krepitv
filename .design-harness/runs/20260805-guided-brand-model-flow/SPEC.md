# Design Specification

## Context

`GuidedSelectionPage` уже содержит поиск модели, вопросы о стене и механизме, Rust/WASM-проверку
совместимости и privacy-safe событие результата. Требуется изменить только вход в этот поток.

## Goal

Сделать первым обязательным действием выбор марки телевизора, вторым — точной модели внутри
марки, затем сохранить существующий технический подбор как шаги три и четыре.

## Non-goals

Новые канонические страницы, цены, загрузка файлов, серверное состояние, новые категории товара,
изменение правил VESA/нагрузки или автоматическое коммерческое ранжирование.

## Inputs

`catalog.models` — проверенные паспорта телевизоров; `catalog.search` — совпадающий поисковый
индекс моделей; query-параметр `model` — безопасная глубокая ссылка на точную модель.

## Constraints

Весь интерфейс по-русски. Марки и количества вычисляются из каталога. Свежий вход не выбирает
первую модель автоматически. Точная query-модель может заранее выбрать марку и заполнить шаг
модели, но пользователь её подтверждает. Список моделей всегда ограничен выбранной маркой.

## States

Default и disabled — первый шаг без марки; focus — видимый фокус select. Empty — выбранная марка
и пустой запрос модели. Loading/error/success относятся к существующей локальной проверке
совместимости на четвёртом шаге. Все состояния сохраняют навигацию назад и выбранную марку.

## Acceptance tests

- Свежий `/podbor/` показывает «Шаг 1 из 4» и не содержит результата случайной модели.
- Марки уникальны, отсортированы по числу проверенных моделей, затем по названию.
- После подтверждения марки открывается шаг модели, а `ModelSearch` получает только её записи.
- Точная модель другой марки не может быть отправлена через отфильтрованный шаг.
- `?model=<точный-id>` выбирает соответствующую марку и открывает шаг подтверждения модели.
- Назад не теряет корректный выбор; смена марки очищает модель, стену, механизм и старый результат.
- Совместимость загружается только на четвёртом шаге после выбора механизма.
- Событие результата остаётся обезличенным и отправляется один раз только после готового результата.
- SSR начинает с выбора марки и сохраняет доступный каталог по маркам без JavaScript.
- 320, 768 и 1440 px не имеют горизонтального переполнения и обрезанного текста.

## Allowed files

Совпадают с `task.json`: страница мастера, новый flow-тест, QA-capture, Rust SSR/sitegen,
сгенерированный `docs/` и текущий evidence-пакет.

## Verification commands

Контрактные flow/result/privacy тесты и Rust SSR-тест; полный `npm run build`; design drift scan.

## Sources and claims

Марки и количества моделей происходят из `data/research/verified-tv-models.json`; внешние
маркетинговые утверждения не добавляются.

## Asset contract

Новых растровых или SVG-активов нет. Используются существующие Tailwind-токены, Phosphor icons и
изображение схемы крепления. Exact UI copy формируется детерминированно в коде.

## Review and rollback

Независимая headless-browser проверка охватывает состояния, клавиатуру и три viewport. Rollback —
откат release-коммита, полная пересборка `docs/` и повторный Pages deploy.
