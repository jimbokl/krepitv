# Visual Direction

## Visual Thesis

«Технический диспетчер»: экран не пугает списком неисправностей, а последовательно
отделяет телевизор, источник, кабель и сигнал вещания.

## Direction Options

1. Длинное дерево решений — отклонено: плохо читается на 320 px.
2. Карточки возможных поломок — отклонено: подталкивает к самодиагностике без данных.
3. Короткий мастер + один ранжированный план — выбран: соответствует реальному решению.

## Selected Direction

Точное продолжение утверждённого KREPI TV: чёрные линейные разделители, оранжевый
только для выбора и действия, синий для проверки, зелёный только для пройденного
шага, красный только для ошибки загрузки.

## Hierarchy And Reading Order

H1 → прямой SSR-ответ → источник просмотра → видимость меню → условные признаки →
кнопка → одна следующая проверка → короткая последовательность → stop condition →
официальное основание → FAQ и внутренний следующий job.

## Composition And Negative Space

На desktop — существующая двухколоночная оболочка 22rem + flexible form. На
mobile — одна колонка, только актуальная группа вопросов. Результат отделён одной
крупной линией; дополнительные варианты скрыты под native details.

## Palette And Typography

Только существующие semantic Tailwind tokens и production fonts. Новых цветов,
теней, градиентов, pills или декоративных карточек нет.

## Responsive Or Sequence Behavior

320 px без горизонтального overflow; tablet/desktop сохраняют порядок; 200%
текста и WCAG spacing не скрывают controls. Фокус после submit переходит на H2
результата; loading/error/retry не сбрасывают выбор.

## Exact-content Layer

Все тексты, source labels, числа и статусы рендерятся детерминированно из кода и
проверяемого source manifest.

## Imagegen Layer And Invariants

None. Визуальный референс уже утверждён, а диагностический интерфейс не нуждается
в растровой иллюстрации; imagegen не должен рисовать точные инструкции.
