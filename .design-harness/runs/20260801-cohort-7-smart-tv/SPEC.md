# Design Specification

## Context

Строгий fixed-wordform Wordstat по России подтвердил 32 685 для «как обновить
телевизор», 16 195 для «как установить приложение на телевизор» и 7 940 для
«как сбросить телевизор до заводских настроек». Варианты одного canonical не
складываются. Текущая органика — 0, gate — 0/7 суток, поэтому это одна последняя
малая high-head когорта перед заморозкой новых URL и измерением.

## Goal

Добавить три самостоятельных canonical с полным SSR-ответом, локальным закрытым
мастером, официальными источниками и fail-closed границами. Сохранить утверждённый
визуальный язык и повысить внутренний приоритет двух крупнейших задач.

## Non-goals

Не добавлять антенную страницу из-за каннибализации, офферы, цены, редиректы,
регистрацию, загрузку пользовательских данных, прошивки, APK-инструкции,
универсальные сервисные меню или брендовые дочерние URL.

## Inputs

Существующий `TvTrafficTaskWizard`, Rust/WASM engine, Rust sitegen, React,
Tailwind-токены, строгий Wordstat snapshot и первичные источники Samsung, LG,
Sony, Google и Яндекса из `task.json`.

## Constraints

Только русский UI и закрытые enum-входы. Точная модель и официальная инструкция
приоритетнее общего бренда. Обновление нельзя прерывать. Приложение нельзя обещать
по одному названию платформы. Полный сброс требует явной готовности потерять
настройки и доступного штатного меню. Все ответы остаются в браузере.

## States

`empty`, `default`, `disabled`, `focus`, `loading`, `error`, `success`,
`needs-check`, `external-path`, `service-boundary`. `external-path` применяется к
не найденному приложению/нехватке места; `service-boundary` — к опасному питанию,
идущему обновлению и сбросу без штатного меню.

## Acceptance tests

- Три уникальных canonical indexable, присутствуют в sitemap и имеют substantive SSR.
- Rust принимает только объявленные enum; неизвестность не превращается в точное меню.
- Идущее обновление никогда не получает инструкцию выключить питание или начать сброс.
- Приложение устанавливается только через подтверждённый официальный магазин;
  `apk-only` не выдаёт универсальную инструкцию sideload.
- Сброс разрешён только при `ready-to-erase + normal-menu`; вывод явно перечисляет
  потерю настроек, каналов, аккаунтов/данных и установленных приложений.
- На трёх страницах ноль Market-ссылок, цен, форм свободного ввода и скрытых редиректов.
- 320/768/1440 px, 200% text zoom, WCAG text spacing и клавиатура не ломают интерфейс.
- Loading блокирует повторную отправку; error сохраняет выборы и даёт retry.

## Allowed files

Совпадают с `task.json`; изменение ограничено engine/sitegen, единым существующим
мастером, SEO-данными/исследованием, тестами, generated artifact и этим harness-run.

## Verification commands

Targeted Rust/sitegen/web, полный `npm run build`, `git diff --check`, design drift,
responsive browser screenshots и production HTTP/TLS/hash/browser smoke.

## Sources and claims

Все source IDs из `task.json` должны совпасть между source manifest, Rust output,
React registry и SSR. Никакая общая инструкция не подменяет руководство точной модели.

## Asset contract

Responsive HTML/CSS/JS/WASM на GitHub Pages. Скриншоты PNG 320×800, 768×1024 и
1440×900. Текст и статусы компонуются детерминированно. Imagegen не используется:
утверждённый Tailwind-референс сохраняется без нового визуального направления.

## Review and rollback

Независимый агент проверяет источники, границы, тесты и реальные скриншоты.
Rollback — один release commit с удалением трёх canonical/tasks/source-map;
DNS, аналитика и affiliate snapshots не меняются.
