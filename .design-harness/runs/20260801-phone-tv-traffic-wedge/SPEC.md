# Design Specification

## Context

KREPI TV расширяется от крепежа к высокочастотной полезной задаче. Wordstat-срез по России зафиксировал 72 811 показов у точного входа «как подключить телефон к телевизору». Страница должна быть самостоятельным продуктом, а не тонкой SEO-статьёй.

## Goal

Сделать компактный кросс-брендовый мастер, который выбирает безопасный способ подключения и явно отделяет подтверждённый маршрут от ручной проверки.

## Non-goals

Не выводить способности из одного бренда или Smart TV; не советовать провод до проверки видеовыхода; не показывать Маркет, цены и партнёрские ссылки; не читать query-параметры; не создавать страницы комбинаций.

## Inputs

Обязательные: iPhone/Samsung Galaxy/другой Android и тип телевизора. Необязательные: задача, одна Wi-Fi, HDMI, разъём телефона и подтверждённый видеовыход Android. Факты — только из официальной матрицы `product-docs/research/PHONE_TO_TV_OFFICIAL_SOURCES_2026-08-01.md`.

## Constraints

Русский публичный UI; существующие Tailwind-токены, шрифты и иконки Phosphor; один canonical; статический GitHub Pages; локальная Rust/WASM-логика; SSR-матрица и источники; без Cloud.ru; без новых цветов, теней, градиентов и длинных открытых списков.

## States

`empty` — до выбора телефона; `default` — телефон выбран, показан шаг ТВ; `disabled` — submit недоступен без двух ответов; `loading` — WASM загружается; `error` — отказ WASM с сохранённым выбором; `retry` — успешное восстановление после первого отказа без сброса выбора; `needs-check` — возможный путь с ручной проверкой; `no-direct-path` — прямой путь не подтверждён; `success` — расчёт завершён одним из безопасных статусов; `focus` — видимый focus-within на native radio. Unknown является валидным ответом, а не ошибкой.

## Acceptance tests

- На 320 px нет горизонтального overflow, интерактивные зоны не меньше 48 px, текст не обрезан.
- На 768 и 1440 px чтение идёт телефон → ТВ → условия → результат.
- Все группы — `fieldset/legend`, focus видим, результат получает программный focus после submit.
- Неизвестный USB-C видеовыход никогда не даёт `ready`; ordinary USB не становится маршрутом.
- SSR содержит один H1, canonical, матрицу пяти способов, предупреждение USB и официальные ссылки.
- React после загрузки сохраняет answer/reference; query не читаются и не отражаются.
- На странице отсутствуют `market.yandex.ru`, affiliate-разметка, цены и персональные данные в аналитике.
- Ошибка и загрузка имеют отдельный читаемый экран; основной выбор не сбрасывается.

## Allowed files

Только пути из `task.json`: движок, sitegen, SEO record, мастер и навигация, связанные тесты/QA, сгенерированные `web`/`docs`, исследования и этот design-run.

## Verification commands

Команды из `task.json`: Rust-матрица, узкие web-тесты, полная production-сборка, синтаксис QA-скрипта и полный security/static/affiliate-аудит статического артефакта.

## Sources and claims

AirPlay, Google Cast, Smart View, USB-C DisplayPort и ordinary USB привязаны к Apple, Google, Samsung, VESA и LG в `task.json`; полный реестр из 21 URL хранится в локальном источнике `official-source-matrix`.

## Asset contract

Финальный артефакт — адаптивный HTML/CSS/JS/WASM, не растровый макет. Скриншоты доказательств: PNG ровно 320×800, 768×1024 и 1440×900. Весь текст и числа рендерятся детерминированно; ImageGen не используется.

## Review and rollback

Независимый субагент проверяет реальный артефакт и скриншоты после команд. Rollback — revert одного release-коммита и возврат предыдущего GitHub Pages artifact; детали в `review.md`.
