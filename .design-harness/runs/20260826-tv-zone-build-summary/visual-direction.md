# Visual Direction

## Visual Thesis

«Монтажная ведомость, которую понимает хозяин квартиры»: высокая информационная плотность, но один главный ответ; тёплый бумажный фон, чёрная техническая сетка, оранжевый акцент действия, зелёный только для доказанного факта.

## Direction Options

1. Инженерная ведомость — строгие рамки, моно-подписи, явные статусы.
2. Карточки интернет-магазина — отклонено: усиливает рекламный вид и размывает проверку.
3. Мастерская-инструкция — полезна ниже для подробностей, но слишком длинна для первого экрана результата.

## Selected Direction

Инженерная ведомость с компактной «обложкой» сборки и прогрессивным раскрытием проверок.

## Hierarchy And Reading Order

H1 результата → статус и точная пара → один следующий шаг → максимум три проверки → якорь к подробному паспорту. В шаге 6: подключения → закрытый измерительный блок → пояснение замера.

## Composition And Negative Space

Summary занимает один устойчивый блок; 2-колоночная раскладка только когда ширины достаточно. На мобильном все факты идут одной колонкой, контролы имеют минимум 44 px, строки не превращаются в горизонтальные таблицы.

## Palette And Typography

Только существующие токены и типографика. Цвет дублируется текстом и иконкой. Числа зазора набираются display/mono, пояснения — обычным гротеском.

## Responsive Or Sequence Behavior

`verified`, `needs-check`, `blocked`, `no-offer` используют одну геометрию. Details не раскрывается автоматически без выбранного подключения. Print скрывает интерактивные кнопки, но оставляет результат, причины и чек-лист.

## Exact-content Layer

Русские заголовки и verdict рендерятся HTML/React, не изображением. Внешние изображения не используются.

## Imagegen Layer And Invariants

None: интерфейс строится из существующих детерминированных компонентов; генеративные растровые материалы не нужны.
