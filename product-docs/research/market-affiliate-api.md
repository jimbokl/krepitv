# API реферальной программы Яндекс Маркета для KREPI TV

Дата проверки: **30 июля 2026 года**.

Область исследования: только официальные документы Яндекс Маркета, Яндекс Дистрибуции и действующее соглашение API. Ниже отдельно отмечены подтвержденные факты, технические выводы, неизвестное и то, что можно проверить только после подключения кабинета.

## Короткий вывод

Для полностью статического KREPI TV на GitHub Pages минимальный надежный путь такой:

1. В кабинете Реферальной программы заключить договор, добавить сайт как площадку и пройти модерацию.
2. В разделе «Реферальная программа» вручную выбрать конкретные карточки с фиолетовым значком и сохранить их канонические URL. Через актуальный affiliate API искать такие товары уже нельзя: `GET /search` не поддерживается с 22 июня 2026 года.
3. На приватном этапе сборки, а не в браузере посетителя, вызвать `GET /partner/link/create` для каждого URL карточки. Метод возвращает реферальную ссылку и моментальный снимок `promise`, `price`, `stockAmount`.
4. Зарегистрировать рекламный креатив, получить ERID и сгенерировать финальную ссылку с параметром `erid` либо провести маркировку штатным интерфейсом кабинета.
5. Сохранить в статические данные/HTML только допущенную ссылку, идентичность товара, фото, время проверки и сведения о маркировке. `promise`, `price` и `stockAmount` должны оставаться в приватном снимке решения. Авторизационный ключ должен оставаться в секрете сборки и не попадать в репозиторий, JavaScript или исходник страницы.
6. По расписанию повторять сборку. При неуспешном ответе, нулевой/отсутствующей награде или отсутствии остатка убирать кнопку покупки либо переводить карточку в нейтральное состояние до следующей проверки.

**Важно:** термин «оплачиваемая ссылка» не означает оплату клика. Актуальная программа платит за квалифицированный заказ; сведения об оплате за клики и метод `GET /stats/clicks` удалены из документации еще в версии 3.23 от 1 августа 2023 года.

## Что подтверждено официально

### Доступ и авторизация

- API позволяет создавать реферальные ссылки и артикулы и получать сведения о заказах.
- Для доступа нужен заключенный договор по Реферальной программе и специальный авторизационный ключ.
- Ключ передается в каждом запросе в заголовке `Authorization: OAuth <token>`.
- Один ключ можно использовать для нескольких одобренных площадок, указывая ID площадки или соответствующий ей CLID.
- Глобальные лимиты: не более 5 запросов в секунду и 400 000 запросов в сутки на один ключ. Текущие остатки лимитов возвращаются в HTTP-заголовках.

Источники: [справка о подключении API](https://yandex.ru/support/market-distr/ru/api), [авторизация](https://yandex.ru/dev/market/affiliate/ru/concepts/authorization), [лимиты](https://yandex.ru/dev/market/affiliate/ru/concepts/limits).

### Фиолетовый значок и выбор товаров

- Все товары с реферальной наградой собраны в авторизованном разделе «Реферальная программа».
- Размер предлагаемого вознаграждения показывается на карточке фиолетовым значком.
- Выдача товаров персонализирована для пользователя; в кабинете доступны фильтрация и поиск.
- После открытия карточки и нажатия фиолетового значка можно выбрать площадку, добавить рекламный токен и скопировать ссылку или артикул.
- Для генерации артикулов площадка должна быть добавлена и одобрена.

Источник: [реферальные ссылки и уникальные артикулы](https://yandex.ru/support/market-distr/ru/partner-links/partner-links).

### Актуальный API не ищет карточки

- В версии 3.25 от 22 июня 2026 года добавлен `GET /partner/link/info`.
- В той же версии из документации удален `GET /search`, потому что запрос больше не поддерживается.
- В текущем справочнике остаются создание ссылок и артикулов, отчеты по заказам, проверка ссылки/артикула и методы маркировки.

Следствие для KREPI TV: affiliate API может преобразовать уже известную карточку в реферальную ссылку, но не может сам найти все кронштейны с фиолетовым значком. Начальный список URL/артикулов нужно получать из кабинета/интерфейса Маркета и вести как собственный кураторский манифест.

Источники: [журнал изменений](https://yandex.ru/dev/market/affiliate/ru/concepts/changelog), [текущий список методов](https://yandex.ru/dev/market/affiliate/ru/reference/all-methods).

### Создание ссылки на конкретную карточку

Метод:

```http
GET https://api.content.market.yandex.ru/v3/affiliate/partner/link/create
Authorization: OAuth <token>
```

Параметры:

- `url` — URL страницы Маркета; для KREPI TV нужен URL конкретной карточки;
- `place_id` — ID площадки из раздела «Блоги» кабинета;
- вместо `place_id` можно передать CLID типа «Партнерские ссылки»;
- `vid` — необязательный идентификатор для раздельной статистики одной ссылки/позиции;
- `erid` — необязательный ERID зарегистрированного креатива; API добавляет его к `url` и `shortUrl` результата.

Пример формы запроса без реальных идентификаторов:

```bash
curl --get \
  -H "Authorization: OAuth $YANDEX_MARKET_AFFILIATE_TOKEN" \
  --data-urlencode "url=https://market.yandex.ru/card/..." \
  --data-urlencode "place_id=$YANDEX_MARKET_PLACE_ID" \
  --data-urlencode "vid=krepitvwallmount01" \
  --data-urlencode "erid=$ERID" \
  "https://api.content.market.yandex.ru/v3/affiliate/partner/link/create"
```

Успешный ответ содержит:

- `link.url` и `link.shortUrl` — готовые реферальные ссылки;
- `pageName`; для карточки товара ожидается `POKUPKI_PRODUCT`;
- `title` и `productPhoto`;
- `promise` — вознаграждение, закрепленное за ссылкой;
- `rewardInUrl` — вознаграждение на момент создания ссылки;
- `price` — цена товара;
- `stockAmount` — доступный для заказа остаток.

Источник: [`GET /partner/link/create`](https://yandex.ru/dev/market/affiliate/ru/reference/get-partner-link-create).

### Реферальный артикул

`POST /partner/article/create` принимает либо `marketArticle`, либо URL вида `https://market.yandex.ru/card/...` в `marketUrl`, а также `place_id` либо CLID типа «Артикулы Маркета». Ответ содержит артикул вида `YM10469939`, название, изображение, награду, цену и остаток. Для той же комбинации маркетного артикула, CLID и VID возвращается уже существующий реферальный артикул.

Для обычной кнопки «Посмотреть на Маркете» на статическом сайте проще применять ссылку, а не артикул: метод ссылок сразу возвращает кликабельный URL и документированно принимает `erid`.

Источник: [`POST /partner/article/create`](https://yandex.ru/dev/market/affiliate/ru/reference/get-partner-article).

### Повторная проверка ссылки или артикула

Новый метод `GET /partner/link/info` принимает реферальный `url` либо `partner_article` и возвращает:

- название и изображение;
- OSKU;
- `fixedPromise` — награду, зафиксированную при создании;
- `promise` — текущую награду, если есть OSKU.

Этот метод подходит для проверки уже опубликованных ссылок, но не возвращает цену и остаток. Если KREPI TV должен обновлять также цену и наличие, при сборке нужно заново запрашивать `GET /partner/link/create` по сохраненному каноническому URL карточки.

Источник: [`GET /partner/link/info`](https://yandex.ru/dev/market/affiliate/ru/reference/get-partner-link-info).

### Награда не гарантируется одним наличием ссылки

- Вознаграждение начисляется за заказ, а не за переход.
- Официальная справка связывает выплату с переходом по реферальной ссылке на товар с фиолетовым значком и заказом этого товара или другой модели из той же карточки.
- В условиях отдельно указано: та же модель и тот же продавец; заказ не позднее 7 календарных дней после первого перехода; покупатель должен получить заказ, не отменить/не изменить его и не оформить возврат в течение 14 дней.
- Фактическая сумма может отличаться от фиолетового значка, если куплен другой вариант товара или итоговая стоимость покупки ниже.
- Справка прямо предупреждает, что она не является публичной офертой или частью договора; окончательные условия определяет договор.

Источник: [выплата вознаграждения](https://yandex.ru/support/market-distr/ru/terms).

### Маркировка и ERID

Для каждого рекламного креатива Яндекс требует ERID и передачу данных в ЕРИР через ОРД. На площадке нужно явно указать:

- пометку **«Реклама»**;
- рекламодателя: **ООО «Яндекс Маркет», ИНН 9704254424**;
- если ERID не встроен в ссылку — `erid: xxxx` в начале текстового блока, на изображении либо в/поверх видео.

Через API доступны:

- `POST https://api.content.market.yandex.ru/v3/affiliate/marking/` — создать или изменить креатив и получить `token` (ERID);
- `GET https://api.content.market.yandex.ru/v3/affiliate/marking/` — получить список зарегистрированных креативов.

Для регистрации креатива официальный API-справочник требует `clid`, `form`, `description` и рекламный материал (`text_data` и/или `media_data`). Для Маркета справка предписывает `service=market`, `type=cpa`, `urls` со всеми ссылками креатива, `okveds=["62.01"]`, а `is_social` и `is_native` не передавать. Для редактирования передается существующий `token`.

После отчетного периода партнер должен передать количество показов креативов. Для части инструментов Яндекс заполняет данные автоматически по визитам на Маркет с соответствующим ERID, но значения нужно проверить; их можно править в кабинете или загружать через Excel. Срок обновления — до конца второго месяца после отчетного периода.

Источники: [маркировка рекламы](https://yandex.ru/support/market-distr/ru/ad-labeling/), [`POST /marking`](https://yandex.ru/dev/market/affiliate/ru/reference/post-creatives), [`GET /marking`](https://yandex.ru/dev/market/affiliate/ru/reference/get-creatives).

## Минимальная техническая схема для статического GitHub Pages

Ниже — инженерный вывод из официальных требований авторизации и методов API. Это не готовая настройка кабинета.

### 1. Приватный манифест кандидатов

В репозитории можно хранить не секретный список, например `data/market-products.json`:

```json
[
  {
    "slug": "tv-wall-mount-01",
    "market_url": "https://market.yandex.ru/card/...",
    "page": "/kronshteyny/.../",
    "vid": "krepitvwallmount01",
    "creative_token": null
  }
]
```

`market_url` добавляется после ручного отбора в реферальном разделе. VID лучше делать стабильным для конкретной страницы/позиции. В документации ошибки для артикула указано ограничение: до 150 символов, только латинские буквы и цифры; безопасно придерживаться его и для ссылок.

### 2. Приватные секреты сборки

Минимум два секрета:

- `YANDEX_MARKET_AFFILIATE_TOKEN`;
- `YANDEX_MARKET_PLACE_ID` либо подходящий `CLID`.

Токен нельзя выполнять в клиентском JavaScript: на GitHub Pages любой такой код и запрос виден посетителю. API вызывается локально перед публикацией или в приватном CI job, а в статический сайт попадает только результат.

### 3. Первая генерация и маркировка

Практическая последовательность для каждой карточки:

1. Вызвать `/partner/link/create` по каноническому URL без ERID и получить реферальную ссылку и снимок товара.
2. Зарегистрировать креатив через `/marking/`, указав фактический текст/медиа и все его целевые ссылки; получить `token`.
3. Повторно вызвать `/partner/link/create` с `erid=<token>`.
4. Опубликовать финальный `link.url` или `link.shortUrl`, пометку «Реклама» и данные рекламодателя.

Эта последовательность — минимальная техническая интерпретация двух официальных методов. В документации не описано, должен ли список `urls` при регистрации уже содержать финальный URL с ERID, из-за чего возникает циклическая зависимость «ссылка → ERID → ссылка с ERID». До массового запуска один креатив необходимо провести целиком в реальном кабинете/тестовом запросе и проверить, как ОРД сохраняет URL. Штатный интерфейс кабинета, где токен добавляется при копировании ссылки, является более безопасным способом первого запуска.

### 4. Генерируемый публичный файл

Сборщик пишет, например, `public/data/market-affiliate.json`:

```json
{
  "tv-wall-mount-01": {
    "href": "https://market.yandex.ru/...",
    "title": "...",
    "checkedAt": "2026-07-30T08:00:00Z",
    "advertiser": "ООО «Яндекс Маркет», ИНН 9704254424",
    "label": "Реклама"
  }
}
```

Если KREPI TV выводит полученные через API название, фото, цену или другие данные Маркета, действует соглашение API: данные нельзя скрывать/модифицировать; нужно разместить логотипы Яндекса и Маркета и текст-ссылку «Данные сервиса Яндекс Маркет» на главную страницу Маркета; данные должны находиться на страницах, связанных с соответствующими товарами. Соглашение также требует учитывать местонахождение пользователя для показываемых данных. Реализация выводит только API-заголовок и `productPhoto` рядом с точной страницей кронштейна и обязательной текстовой атрибуцией. Цена, остаток и обещанная награда используются только как фильтр публикации: пользователю предлагается проверить региональную цену непосредственно на Маркете. Вопрос обязательного графического логотипа нужно подтвердить по договору до первого реального креатива.

Источник: [пользовательское соглашение API](https://yandex.ru/legal/market_affiliate_api/ru/).

### 5. Обновление статического сайта

Рекомендуемый цикл сборки:

1. По каждому сохраненному `market_url` вызвать `/partner/link/create` с теми же `place_id`/CLID, VID и ERID.
2. Проверить HTTP-код, `status == "OK"`, наличие `link.url`, числовое значение `promise` и `stockAmount`.
3. После приватного решения сформировать публичный JSON/HTML заново, удалив
   `promise`, `price` и `stockAmount` и пропустив только допущенные офферы.
4. Опубликовать новый статический артефакт GitHub Pages.

Разумный консервативный критерий публикации CTA: `status=OK`, ссылка непустая, `promise > 0`, `stockAmount > 0`. **Это инженерное правило KREPI TV, а не официальная гарантия Яндекса и не документированное тождество фиолетовому значку.** Если проверка не пройдена, карточку лучше оставить информационной без кнопки либо скрыть ссылку до следующей сборки.

Периодичность зависит от того, публикуется ли динамика:

- ссылка и фото — проверка дважды в сутки при клиентском TTL 48 часов;
- цена/наличие/награда на странице — нужна существенно более частая сборка, но API не гарантирует своевременность данных, а статический сайт все равно будет показывать снимок;
- для максимально низкого юридического и UX-риска не публиковать цену и обещанную сумму вознаграждения посетителю, а обновлять их только внутренне.

Скрипт должен ограничивать скорость до 5 запросов/с, уважать заголовки лимитов
и ретраить временные ошибки с задержкой. Текущий production-контур после
исчерпания повторов снимает CTA по строгому fail-closed правилу. Если позже
понадобится last-known-good, его полный снимок с входами решения можно хранить
только в долговечном приватном хранилище, а не в публичном JSON.

## Требует кабинета

До реализации нельзя получить из открытой документации; нужны действия владельца и реальный аккаунт:

1. Заключенный договор и статус участника программы.
2. Добавленная, подтвержденная и одобренная площадка KREPI TV. Официальная справка указывает модерацию до 24 часов после отправки площадки; заявление на договор — до двух дней.
3. Реальные `place_id` и/или CLID нужного типа.
4. Авторизационный ключ, полученный под связанным Яндекс ID.
5. Видимость конкретных карточек кронштейнов в персонализированном реферальном разделе и фактические значения фиолетовой награды.
6. Возможность регистрации креатива через ОРД Яндекса, фактический формат возвращаемого `token`/ERID и корректность повторной генерации ссылки с ним.
7. Подтверждение, что сайт и его конкретные страницы прошли модерацию как разрешенный источник трафика.
8. Финальные договорные условия начисления и документы по выплатам/отчетности.

Источник: [как стать партнером](https://yandex.ru/support/market-distr/ru/partner).

## Неизвестно или не гарантируется официальными документами

1. **Нельзя публично проверить список доступных фиолетовых товаров без кабинета.** Открытого актуального метода поиска в affiliate API нет.
2. **Нет документированного API-флага `purpleBadge=true`.** Связь `promise > 0` с отображением фиолетового значка логична, но в справочнике API прямо не заявлена.
3. **Не гарантировано, что повторный `/partner/link/create` вернет тот же URL.** Поэтому опубликованный href следует брать из каждого успешного результата сборки, а не конструировать вручную.
4. **Не гарантирована неизменность `promise`, цены или остатка.** `/partner/link/info` различает зафиксированную и текущую награду, а соглашение предоставляет данные «как есть» без гарантии точности, полноты и своевременности.
5. **Нельзя считать показанный `promise` гарантированной выплатой.** Итог зависит от заказа, продавца, модели, срока атрибуции, получения и возврата, а также договора.
6. **В API артикула не документирован параметр `erid`.** Интерфейс Маркета предлагает добавить рекламный токен при копировании артикула, но `POST /partner/article/create` такого входного поля не описывает. Для сайта предпочтительнее реферальная ссылка.
7. **В официальной справке по маркировке метод назван `POST/creatives/`, а актуальный технический справочник показывает `POST /marking` и URL `/v3/affiliate/marking/`.** Для кода следует ориентироваться на технический справочник, но до массового применения проверить запрос с реальным токеном.
8. **Не описана атомарная программная последовательность URL ↔ ERID.** Требование передать все URL креатива и необходимость затем добавить ERID к ссылке создают неоднозначность; ее нужно проверить одним реальным креативом.
9. **Нет официальной рекомендуемой частоты обновления ссылок для статических сайтов.** Ежедневная/более частая сборка — инженерный выбор KREPI TV.
10. **Не гарантирована бессрочная поддержка методов.** Яндекс оставляет право менять, приостанавливать и обновлять API; журнал изменений нужно контролировать перед релизами.

## Рекомендуемое решение для MVP

Для первого релиза KREPI TV:

- вручную отобрать 10–30 релевантных карточек в кабинете;
- использовать только `GET /partner/link/create`, не артикулы;
- создать по одному стабильному VID на каждую страницу/позицию;
- провести маркировку первых ссылок через кабинет, пока не подтвержден API-цикл ERID;
- держать OAuth-ключ только в секрете сборки;
- обновлять ссылки дважды в сутки, сохраняя предыдущий снимок при техническом сбое;
- на сайте показывать собственное описание товара, пометку «Реклама», рекламодателя и кнопку с актуальным реферальным href;
- рядом с API-блоком показывать требуемую соглашением атрибуцию «Данные сервиса Яндекс Маркет» и логотипы;
- не показывать пользователю API-цену, остаток и обещанную награду на MVP, используя их только как фильтр публикации;
- при расширении автоматизации зарегистрировать креативы через `/marking/` и отдельно подтвердить корректность отчетности по показам.

Такой путь совместим с полностью статическим GitHub Pages: серверный runtime не нужен, а чувствительные запросы выполняются только до публикации.
