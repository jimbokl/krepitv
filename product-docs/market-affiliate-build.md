# Безопасная build-time подготовка предложений Маркета

Этот каркас хранит известные карточки, принимает уже очищенные результаты приватной проверки и формирует снимок решений о публикации. Он намеренно:

- не обращается к партнерскому API по сети;
- не читает секреты из окружения;
- не пишет данные во frontend или `docs/`;
- не содержит реальных партнерских ссылок;
- удаляет `affiliate_href` у любого предложения, которое нельзя публиковать.

Авторизационный секрет существует только внутри отдельного приватного job/secret manager. Он не должен попадать в git, документацию, логи, JSON-пакеты, браузерный JavaScript или артефакты GitHub Pages.

## Состав

- `data/affiliate/market-products.json` — отслеживаемые карточки. Сейчас список пуст: реальные URL и ERID добавляются только после одобрения площадки и отдельного решения владельца.
- `schemas/market-affiliate-source.schema.json` — JSON Schema исходного манифеста.
- `schemas/market-affiliate-batch.schema.json` — JSON Schema очищенного пакета проверок от приватного job.
- `schemas/market-affiliate-snapshot.schema.json` — JSON Schema результирующего снимка.
- `scripts/affiliate/validate.mjs` — строгий валидатор данных и инвариантов безопасности.
- `scripts/affiliate/build-snapshot.mjs` — детерминированное объединение манифеста и пакета проверок.
- `tests/fixtures/affiliate/` — только фиктивные адреса домена `example.invalid`.

## Контракт исходного манифеста

Каждая запись `cards[]` содержит:

- `id` — стабильный внутренний идентификатор;
- `market_source_url` — исходная HTTPS-карточка товара, не партнерская ссылка;
- `page_path` — будущая связанная страница KREPI TV, но каркас сам ее не изменяет;
- `vid` — стабильный VID из 1–150 латинских букв и цифр;
- `creative.form` и `creative.content_revision` — форма и версия рекламного материала;
- `creative.erid` и `creative.registered_at` — публичная маркировка либо два `null`, если креатив еще не зарегистрирован;
- `creative.disclosure` — обязательные публичные данные маркировки: «Реклама», ООО «Яндекс Маркет», ИНН 9704254424.

ERID допустим в репозитории как публичный идентификатор рекламного креатива. Авторизационные данные, API-ключи и произвольные `token`-поля запрещены валидатором.

## Контракт очищенного пакета проверок

Приватный fetch job создает `.private/market-affiliate-batch.json`. Он обязан оставить только:

- `id` и точный `market_source_url` из манифеста;
- `status`: `ok`, `unavailable` или `error`;
- готовый `affiliate_href` только при `status=ok`;
- целочисленные `promise`, `price`, `stock` без изменения единиц ответа API;
- UTC-время `checked_at`;
- один нормализованный `error_code` без сырого текста ответа.

Сырые HTTP-заголовки, тело ошибки, параметры авторизации и логи сетевой библиотеки в пакет не включаются.

## Запуск приватного job

Рекомендуемая граница ответственности:

1. Внешний приватный fetch step получает секрет из secret manager, вызывает API и сразу выбрасывает заголовки авторизации.
2. Fetch step записывает очищенный пакет в `.private/market-affiliate-batch.json`. Каталог `.private/` исключен из git.
3. Репозиторный валидатор проверяет пакет:

   ```bash
   node scripts/affiliate/validate.mjs \
     --kind batch \
     .private/market-affiliate-batch.json
   ```

4. Build step объединяет пакет с исходным манифестом:

   ```bash
   node scripts/affiliate/build-snapshot.mjs \
     --source data/affiliate/market-products.json \
     --batch .private/market-affiliate-batch.json \
     --out .private/market-affiliate-snapshot.json
   ```

5. До будущей отдельной задачи снимок остается приватным артефактом. Этот каркас не копирует его в `web/`, `docs/` и не добавляет ссылки в UI.

CLI дополнительно запрещает читать production-пакет вне `.private/` и записывать снимок вне `.private/`. Тестовый режим с `example.invalid` принимает исходные файлы только из `tests/fixtures/`.

В CI следует отключить трассировку shell-команд для fetch step, маскировать секрет средствами платформы, запрещать вывод тела запроса и не сохранять сетевые дампы. Если приватный fetch step завершился неуспешно, предыдущий опубликованный результат нельзя заменять неполным пакетом.

## Правило `publishable`

Снимок получает `publishable=true` только если одновременно:

- проверка вернула `status=ok`;
- `promise > 0`;
- `stock > 0`;
- у креатива есть ERID и время регистрации;
- `affiliate_href` использует HTTPS и содержит тот же ERID в query-параметре.

Иначе ссылка удаляется из снимка, а `eligibility` принимает одно из значений: `unmarked`, `no_reward`, `out_of_stock`, `unavailable`, `error`.

Публичный компонент `AffiliateOffer` дополнительно работает по принципу fail closed: он рендерит только прямой HTTPS-адрес `market.yandex.ru` с совпадающим ERID, показывает маркировку и ставит `rel="sponsored nofollow noopener noreferrer"`. Внутренние `/go/`-ссылки, сторонние сокращатели и скрывающие назначение редиректы не используются. Пользователь и поисковый робот получают один и тот же `href`.

Компонент не является источником собственной ценности страницы. Расчёт совместимости, источники характеристик, методика и инструкции остаются доступными независимо от наличия офферов; если подходящего промаркированного оффера нет, компонент просто не выводится.

Это внутренний консервативный критерий KREPI TV, а не обещание выплаты со стороны Маркета.

## Политика для поисковых систем

KREPI TV не скрывает назначение партнёрского перехода от роботов и не показывает им иной URL, чем пользователю. Google прямо допускает монетизацию партнёрскими ссылками, если они помечены `rel="sponsored"`, а страница добавляет самостоятельную пользу; маскирующий редирект для обхода распознавания создаёт ненужный риск нарушения правил о deceptive redirects.

Практическое правило проекта:

- технический ответ, расчёт, источники и ограничения доступны до рекламного блока и без него;
- описание и выводы KREPI TV не копируются из карточки магазина;
- опубликованный `href` ведёт прямо на длинный `link.url` Маркета, одинаковый для пользователя и робота;
- все коммерческие ссылки имеют `rel="sponsored nofollow noopener noreferrer"`;
- факт клика измеряется клиентским событием аналитики без изменения адреса назначения;
- `/go/`, сторонние сокращатели, JavaScript-подмена ссылки и условная выдача по User-Agent запрещены тестами и сборкой.

Официальные ориентиры: [квалификация исходящих ссылок](https://developers.google.com/search/docs/crawling-indexing/qualify-outbound-links) и [правила Google о thin affiliation и deceptive redirects](https://developers.google.com/search/docs/essentials/spam-policies).

## Проверки

```bash
npm run affiliate:validate
npm run affiliate:test
```

Для fixture-файлов валидатор имеет отдельный флаг `--allow-example-hosts`. В production этот флаг запрещено использовать: штатный режим принимает только `market.yandex.ru`, а для входных карточек дополнительно требует путь `/card/`.

Корневая команда `npm run verify` также запускает обе проверки. Тесты не выполняют сетевых запросов и используют только `example.invalid`.

## Перед первым реальным запуском

1. Одобрить площадку и получить ее идентификаторы в кабинете.
2. Вручную отобрать карточки с реферальной наградой.
3. Зарегистрировать креативы и проверить цикл ERID на одной записи.
4. Реализовать приватный fetch step за пределами публичного артефакта.
5. Провести security review его логирования и хранения секретов.
6. Только отдельной задачей решить, какие поля и как встраивать в UI с обязательной маркировкой и атрибуцией.

Официальные ограничения и нерешенные вопросы API зафиксированы в `product-docs/research/market-affiliate-api.md`.
