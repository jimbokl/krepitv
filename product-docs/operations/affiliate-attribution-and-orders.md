# Атрибуция переходов и приватный учёт заказов

Обновлено: 31 июля 2026 года.

## Три уровня размещений

- Базовый товарный снимок `data/affiliate/public-offers.json` обслуживает
  собственную карточку каждого кронштейна.
- Шесть существующих SEO-хабов используют отдельный снимок
  `data/affiliate/public-hub-offers.json`: 16 размещений с собственными
  `placement_id` и `VID`.
- Все 80 карточек телевизоров используют
  `data/affiliate/public-model-offers.json`. Детерминированный манифест
  `data/affiliate/model-page-placements.json` задаёт 239 возможных размещений:
  не более трёх проверенных вариантов на модель. У каждого сочетания
  `модель × позиция × кронштейн` есть отдельные `placement_id` и `VID`.

На контрольном API-check 31 июля публичный модельный снимок содержал 232 из
239 размещений. Это не постоянная квота: недоступное или не подтверждённое API
предложение автоматически отсутствует, а карточка модели продолжает работать
как независимая проверка совместимости.

На модельной странице коммерческий блок находится над полным каталогом и
показывает только её собственные размещения в порядке `rank` 1–3. Полный список
совместимых кронштейнов сгруппирован по брендам и ведёт на внутренние страницы;
он не размножает одну партнёрскую ссылку десятки раз. Поэтому `VID` заказа
однозначно указывает не только товар, но и модельную посадочную с позицией CTA.

- Ссылка создаётся официальным API Яндекс Маркета и ведёт напрямую на
  `market.yandex.ru`. Редиректов, маскировки и числовой цены на сайте нет.
- Длинный необязательный текст «Партнёрская ссылка на Яндекс Маркет…» удалён
  из интерфейса. Production-проверка запрещает возвращение любого его
  фрагмента. Обязательная маркировка рекламного режима остаётся fail-closed.

## Автоматическое обновление ссылок

Workflow `.github/workflows/affiliate-health.yml` дважды в сутки:

1. проверяет базовый товарный манифест, 16 SEO-размещений и детерминированный
   модельный манифест относительно текущего каталога и графа совместимости;
2. получает отдельную официальную ссылку для каждого `VID`;
3. публикует только свежие и доступные предложения без цены, остатков и
   внутренних чисел API;
4. строго проверяет три публичных снимка, собирает весь статический production
   и сверяет JSON вместе со всеми затронутыми хабами, моделями и товарами.

Если предложение недоступно или API не подтвердил его, соответствующая CTA
исчезает. Старый URL не сохраняется.

## Приватный учёт заказов

Workflow `.github/workflows/affiliate-orders.yml` выполняется раз в сутки.
OAuth и HMAC-ключ хранятся только в GitHub Secrets. В репозиторий, GitHub
Cache, лог и сохраняемый artifact не попадают OAuth, исходный `orderId`, HMAC
заказа, VID, корзина, товары, промокод, тариф или ответ API. На runner сырой
реестр существует только во время job и уничтожается в финальном шаге;
следующий запуск заново читает окно API от фиксированной контрольной даты.

После полного чтения окна отдельная строгая проекция формирует один месячный
агрегат версии 2. В нём сохранены прежние общие итоги: число `APPROVED`, сумма
подтверждённого `payment` в копейках, текущие `NEW`/`ON_HOLD`, отмены, карантин
и технические размеры API-окна. Диагностическая сумма текущих pending-заказов
остаётся только в общем блоке с явной пометкой «Не является подтверждённой
выручкой»; в разрезе победителей никаких pending/cancelled payment нет.

В этот же файл добавлен `attribution_winners`: строки группируются только по
публичным контролируемым координатам
`surface × landing_path × entity_id × rank`. `rank` хранится для `seo_hub` и
`model_page`, где позиция карточки действительно различает эксперимент; для
собственной страницы товара он равен `null`. Две ревизии внутреннего
размещения с одинаковыми публичными координатами схлопываются в одну строку.
Строка содержит четыре счётчика `APPROVED`/`NEW`/`ON_HOLD`/`CANCELLED` и
единственное денежное поле — `approved_payment_kopecks`.

Семантика окна совпадает с общими итогами: `APPROVED` и `CANCELLED` относятся
к выбранному московскому месяцу по текущему `updated_at`, а `NEW` и `ON_HOLD`
показывают текущее незрелое состояние. Суммы строк и обезличенного блока
`unattributed` обязаны точно сходиться с общими итогами; несходимость прерывает
workflow.

Исполняемый валидатор и декларативная схема
`schemas/affiliate-orders-monthly-aggregate.schema.json` закрыты по точному
списку полей на каждом уровне. В сохраняемом файле запрещены `VID`,
`placement_id`, `CLID`, исходные и HMAC-ключи заказов, OAuth/HMAC-секреты и
произвольный текст API. `landing_path` и `entity_id` берутся только из полностью
проверенного placement index; даже неиспользованная запись с небезопасными
координатами останавливает сборку.

Общий агрегат, рейтинг и короткий лидер выводятся в job summary и сохраняются
одним точным GitHub Actions artifact на 90 дней. Upload получает путь ровно к
`aggregates/YYYY-MM.json`, без wildcard и каталогов с сырым состоянием.
Artifact не используется как вход следующего запуска и не может повлиять на
расчёт; исходное состояние, снимок наблюдений и приватный отчёт по отдельным
размещениям никогда не загружаются.

Локальное состояние находится только в `.private/affiliate-orders/` и
содержит HMAC заказа, `VID`, даты, статус и вознаграждение в целых копейках.
Синхронизация сверяет `VID` одновременно с базовым, хабовым и модельным
манифестами; неизвестные значения помещаются в карантин. В локальном режиме
курсор продвигается только после успешного получения всех страниц API, при
следующем запуске используется перекрытие 48 часов.

Приватный диагностический отчёт по-прежнему может группировать наблюдения по
внутренним размещениям без исходного `orderId`; он остаётся только локально и
не является долговечным artifact. Для stop/scale решений используется новый
обезличенный рейтинг: он позволяет сравнить посадочную страницу, товар и
позицию CTA, но не позволяет восстановить внутренний идентификатор ссылки или
заказа.

Подтверждённым доходом считается только поле `payment` у заказа с текущим
статусом `APPROVED`. `NEW`, `ON_HOLD`, тесты, переходы и отменённые заказы в
доход не включаются.

## Контрольный экран партнёрской статистики

Отчёт Маркета находится по адресу
`https://market.yandex.ru/money/referral-statistics`. Проверка во внешнем
Chrome 31 июля 2026 года в 11:00 по Калининграду показала за период
1–31 июля:

- 1 переход;
- 0 заказов;
- 0 ₽ награды;
- 0% отмен;
- единственная строка — «Кронштейн для телевизора Onkron TM5-BW», 1 переход.

Это отдельный контроль источника, а не финансовый результат. Переход мог быть
тестовым или прямым и не доказывает органический трафик. Пока заказ не появился
в партнёрском отчёте и не получил финальный статус `APPROVED`, базовый результат
остаётся **0 заказов и 0 ₽ подтверждённого вознаграждения**.

## Команды оператора

```bash
npm run affiliate:validate-hubs
npm run affiliate:check-hubs
npm run affiliate:build-hub-snapshot
npm run affiliate:publish-hub-snapshot
npm run affiliate:validate-hubs-public

npm run affiliate:check-model-manifest
npm run affiliate:validate-models
npm run affiliate:check-models
npm run affiliate:build-model-snapshot
npm run affiliate:publish-model-snapshot
npm run affiliate:validate-models-public
```

Для заказов переменные `YANDEX_MARKET_AFFILIATE_OAUTH` и
`KREPITV_ORDER_HMAC_SECRET` должны передаваться через окружение:

```bash
npm run affiliate:orders-sync -- --backfill-start 2026-07-30T00:00:00+03:00
npm run affiliate:orders-report -- --month 2026-07
npm run affiliate:orders-aggregate -- --month 2026-07
npm run affiliate:orders-winners -- --month 2026-07
```

`affiliate:orders-aggregate` сохранён как совместимый псевдоним. Обе последние
команды создают один и тот же безопасный агрегат общих итогов и победителей;
для воспроизводимого запуска можно явно передать все три placement-манифеста.

У `orders-sync` пути к хабовому и модельному манифестам имеют безопасные
значения по умолчанию; для воспроизводимой диагностики их можно передать явно:

```bash
npm run affiliate:orders-sync -- \
  --hub-placements data/affiliate/seo-hub-placements.json \
  --model-placements data/affiliate/model-page-placements.json \
  --backfill-start 2026-07-30T00:00:00+03:00

npm run affiliate:orders-winners -- \
  --month 2026-07 \
  --manifest data/affiliate/market-products.json \
  --hub-placements data/affiliate/seo-hub-placements.json \
  --model-placements data/affiliate/model-page-placements.json \
  --out .private/affiliate-orders/aggregates/2026-07.json
```
