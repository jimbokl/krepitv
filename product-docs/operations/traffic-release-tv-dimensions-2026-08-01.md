# Traffic release: размеры телевизоров по диагонали

Дата решения: 01.08.2026. Статус: опубликовано и технически проверено на
production. Индексация и органический трафик этим документом не
подтверждаются.

## Ближайшая цель

Достичь **1001+ легитимного уникального посетителя в сутки семь полных суток
подряд**. Владелец, разработка, автоматические проверки, боты и внутренние
переходы исключаются. Показы, HTTP-ответы, IndexNow, количество URL в индексе и
тестовые заходы посетителями не считаются. Доход и 100 000 ₽ в месяц остаются
следующей целью после прохождения порога площадки.

## Трафиковая гипотеза

Выпускается один canonical:
`https://krepitv.ru/razmery-televizora-po-diagonali/`. Страницы по отдельным
диагоналям из этого кластера не создаются.

Точно-фразовый срез Wordstat по России, регион `225`, `Top queries`, все
устройства, от 01.08.2026 показал **9 787** для формулировки
`телевизор 55 дюймов размеры`, **7 547** для
`телевизор 65 дюймов размеры`, **4 703** для
`телевизор 43 дюйма размеры` и **4 270** для
`диагональ телевизора в см таблица`. Значения разных формулировок пересекаются,
не суммируются и не являются прогнозом посещаемости.

Простой перевод дюймов в сантиметры уже встречается в российской выдаче.
Отстройка KREPI TV — три задачи на одной странице: размеры активного экрана
16:9 по диагонали, восстановление диагонали по реальному прямоугольнику и подбор
максимальной стандартной диагонали для ниши с зазором. Для моделей из
проверенной базы дополнительно проверяется паспортный корпус.

## Состав кандидата

- Геометрия, ограничения и проверка корпуса выполняются в Rust/WASM.
- React управляет состояниями, Tailwind сохраняет утверждённый дизайн KREPI TV.
- Два экрана можно сравнить в одном масштабе; схема строится детерминированным
  SVG без передачи размеров на сервер.
- В исходном HTML доступна таблица 32″, 43″, 50″, 55″, 65″, 75″ и 85″ с явной
  границей между активной областью и корпусом.
- На странице нет цен, ссылок на Яндекс Маркет, партнёрского CTA или длинной
  товарной простыни. Пользовательская ценность сохраняется без монетизации.

## Доказательства готовности до production

- Rust: 55 тестов пройдено.
- Sitegen: 27 тестов пройдено.
- Web: 117 тестов пройдено, включая обязательную проверку DOM после client
  boot в headless Chrome.
- Catalog: 10 тестов, affiliate: 75, IndexNow: 10, analytics: 43 — пройдены.
- Полная сборка, `verify` и проверка русского интерфейса прошли.
- Проверки security, static, affiliate и design прошли; независимое ревью и
  production-проверка входят в финальный gate.

Эти проверки доказывают готовность кандидата, но не публикацию, индексацию,
позиции или посещаемость.

## Production gate

1. Рабочее дерево содержит только ожидаемые изменения, release-коммит
   воспроизводим из чистого checkout.
2. Полная сборка, тесты, `verify`, четыре аудита и design drift проходят на
   release-кандидате.
3. HTML содержит один H1, один self-canonical, русские метаданные, SSR-таблицу
   из семи строк и не содержит ссылок на Маркет.
4. URL находится в sitemap ровно один раз; ссылки на него есть с главной,
   планировщика стены, расчёта расстояния, каталога моделей и ключевых страниц
   43″/55″/65″.
5. После деплоя совпадают хеши HTML, sitemap, JS и WASM; HTTPS отвечает 200,
   три режима и точная модель работают на production, а на 320/768/1440 px и
   при 200% текста нет горизонтального переполнения.

## Измерение после выпуска

Ежедневно фиксируются реальные внешние пользователи, источники, поисковые
посадочные, запросы, показы, клики и `result_completed`. Первое решение о
расширении или переработке принимается по query→page сигналам; до этого
canonical не размножается по диагоналям.

## Rollback

При ошибке WASM, неверном canonical, Market-ссылке, поломке соседнего интента
или критической проблеме интерфейса откатывается один release-коммит через
`git revert`. Из sitemap удаляется только новый URL; данные моделей,
партнёрские снимки и настройки аналитики не изменяются. После отката повторно
проверяются HTTPS, sitemap и соседние калькуляторы.
