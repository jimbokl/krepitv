# SEO, AEO, GEO и скорость — спринт 30 сентября 2026

## Задача и исходные данные

Улучшить существующие ответы и мобильную загрузку, сохранить утверждённый дизайн, источники, работающие инструменты и прямые ссылки Маркета. GEO означает видимость в генеративных ответах, а не создание геостраниц.

Открытый пользователем PageSpeed Insights: измерение 30.09, Lighthouse 13.5. Мобильный отчёт: performance 73, FCP 3,5 с, LCP 4,8 с, TBT 30 мс, CLS 0, SI 4,8 с. Десктоп: performance 100, FCP 0,3 с, LCP 0,4 с, TBT 0 мс, CLS 0,033, SI 0,6 с. Accessibility 100, SEO 100, best practices 96 в обоих режимах. CrUX сообщает «Нет данных»: полевые Core Web Vitals неизвестны, лабораторные показатели не заменяют их.

Свежая Search Console, финальное окно 01–28.09: 2 483 показа, 57 кликов. Это не посетители. Кандидаты по страницам: зависание ТВ — 97 показов, 0 кликов; электроэнергия — 102 и 0; кронштейн 65″ — 64 и 0. Данных пока недостаточно для причинного вывода о последних релизах.

## Реализация и проверка

1. Критический CSS из реального статического HTML; полный CSS загружается отдельно, без JS остаётся резервная таблица стилей. Проверить отсутствие пустого первого экрана, SSR-ответы и визуальные состояния инструментов.
2. Вариативные Roboto Condensed и IBM Plex Sans вместо отдельных файлов каждого веса; приоритет кириллицы. Сохранить гарнитуры, размеры и доступность.
3. Адаптивные варианты пяти повторяемых изображений. Оригиналы, alt, размеры, lazy/eager и приоритет не теряются; выбранная картинка не является скрытым SEO-контентом.
4. Три страницы со спросом: заголовки под наблюдаемый интент, заметный короткий ответ из существующего проверенного текста. На 65″ явно разделить совместимость телевизора и проверку стены.
5. Исправить адреса HowToStep: каждая ссылка ведёт к своему видимому шагу. Объединить идентичность издателя; не выдавать дату редакционной проверки за неизвестную дату публикации.
6. Разрешить расширенные превью на индексируемых страницах; сохранить noindex там, где он задан. Не добавлять фиктивные отзывы, FAQ-разметку ради расширенного сниппета или обещания AI-цитирования.
7. Полный build/test gate, no-JS и браузерная проверка мобильного/десктопного layouts, HTTPS/sitemap/hash после релиза; повторный PSI в обоих режимах. Сравнивать лабораторные прогоны с учётом их вариативности.

## Что не является исправлением

GitHub Pages задаёт собственный TTL: статический файл `_headers` не изменит его. TTL внешней Метрики не управляется этим проектом. Ошибка разрешения DNS WebSocket Метрики в PSI не доказывает дефект инструмента; отключение аналитики ради балла скрывает проблему, а не решает её.

Google не требует специального AI-файла или особой разметки для AI Overviews/AI Mode. Индексируемость, понятный текст, источники и соответствующая видимому содержимому разметка — основа, но не гарантия включения в ответ. [Google: AI-функции](https://developers.google.com/search/docs/appearance/ai-features), [правила структурированных данных](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

Работа с LCP опирается на цепочку загрузки и время отрисовки, а не только на сжатие картинки. [Оптимизация LCP](https://web.dev/articles/optimize-lcp), [полевые и лабораторные Web Vitals](https://web.dev/articles/vitals). Критические стили выделяет [Beasties](https://github.com/danielroe/beasties) на этапе сборки, без нового сервера.
