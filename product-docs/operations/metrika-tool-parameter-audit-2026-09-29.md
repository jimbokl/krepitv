# Диагностика событий инструментов — 29 сентября 2026

Цель — понять, какие инструменты запускают и доводят до результата, не принимая число событий за число людей. Использованы только завершённые дни и приватные отчёты Метрики; ответы пользователя, поля форм и идентификаторы посетителей не выгружались в этот документ.

## Что исправлено в измерении

Прежний запрос параметров цели API отклонял. Скрипт `scripts/analytics/metrika-funnel.mjs` теперь использует поддерживаемый отчёт `goal_params`: фильтр по конкретной цели, измерения `ym:ep:actionGoal` и `ym:ep:eventParamsLevel1…5`, метрику `ym:ep:eventsNumber`. Из параметров в публично описываемую сводку проходят только заранее известные ID инструментов. Исходные агрегаты достижений целей получаются отдельным запросом и не заменяются числом событий с параметрами.

Источники метода: [документация Яндекса о параметрах целей](https://yandex.ru/dev/metrika/ru/stat/attributes/event_paramsevents_/event_params), [набор отчётов Метрики](https://yandex.ru/dev/metrika/ru/stat/presets/preset_content), [метрики параметров событий](https://yandex.ru/dev/metrika/ru/stat/metrics/event_params/event_params).

В органическом срезе 26–28 сентября Метрика наблюдала 27 уникальных посетителей и 4 перехода на Маркет. Разбивка инструментов относится ко **всем** источникам, а не к этим 27 посетителям. События одного инструмента не соединены по сессиям или людям, поэтому отношение результатов к запускам не является когортной конверсией даже при совпадении общих счётчиков.

Здесь нет подтверждения, что ноль результатов вызван поломкой WASM, недоучётом, неочевидной кнопкой или уходом пользователя. Последующий шаг — проверить другие полные короткие окна тем же способом. До выяснения причин агрегаты целей и события параметров показывать отдельно.

## Локальная проверка пути пользователя

29 сентября сценарии монтажного комплекта и подбора винтов пройдены в изолированном браузере с отключённой отправкой в Метрику. Проверка в `scripts/qa/capture-page.mjs` теперь записывает только имена контролируемых событий, ID инструмента и тип результата. Она не сохраняет текст ввода и не создаёт тестовые визиты в production-аналитике.

- Монтажный комплект на 390 и 1440 CSS px: пустое состояние не отправляет событий; шаги выбора дают ровно один `tool_usage`; финальная карта после проверки кабелей даёт один `result_completed`. Для состояний загрузки, ошибки и промежуточного выбора преждевременного завершения нет.
- Подбор винтов на 390 и 1440 CSS px: пустое состояние не отправляет событий; неизвестная модель и модель без проверенного паспорта дают один запуск без ложного завершения; точная модель с паспортом даёт один запуск и один результат `mount_screws_found`.
- В этих прогонах горизонтального переполнения не было. Снимки и полные логи лежат только в `.private/qa/`.

Это доказывает локальную генерацию событий при заданном пути, **но не доставку целей в Метрику и не завершение задач реальными посетителями**. Историческое расхождение 14/0 против 20/6 остаётся без установленной причины. Следующая проверка — новые полные дни после изменения разметки запуска, отдельно по агрегатам целей и параметрам событий; если ноль завершений сохранится при наблюдаемых запусках, исследовать конкретные состояния без вывода о пользователях из одного счётчика.

## Точность события запуска после аудита

Отдельно обнаружен риск ложного `tool_usage`: граница монтажного комплекта охватывала всю страницу, включая навигацию, а граница подбора винтов — весь каталог со ссылками. Делегированный обработчик мог принять обычный клик внутри этих областей за запуск инструмента. Это **возможность ошибки измерения**, а не доказательство, что все прежние старты были ложными; приведённые выше данные не исправляются задним числом.

Границы сужены до элементов управления. Для монтажного комплекта старт дают ввод или изменение выбора марки, модели и следующих параметров; для винтов — ввод, изменение, отправка формы либо выбор предложенной модели. Клики по ссылкам и навигации стартом не считаются. Тесты проверяют фильтрацию и однократное событие на инструмент/путь; полный build прошёл. Первые завершённые дни после публикации нужно анализировать как **новую методику**, а не как прямое продолжение прежнего ряда. Это исправление не объясняет расхождение агрегатов целей и параметров за 15–28 сентября.

Отчёты сохранены только в `.private/`; автоматические тесты проверяют URL метода, отсутствие токена и произвольного пользовательского значения в результате, а также несовпадающие ряды. Изменение скрипта не меняет сайт. Однако полный обязательный `npm run build` пересобрал двоичный WASM-артефакт из текущих исходников, поэтому его отличие нужно проверять и публиковать как часть обычного релиза, не выдавая за новую пользовательскую функцию.
