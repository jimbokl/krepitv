# KREPI TV — измерение трафика и переходов

Дата фиксации: 31 июля 2026 года.

## Текущее состояние

- Создан отдельный счётчик Яндекс Метрики `111176777` для `krepitv.ru`.
- Вебвизор и карты отключены. Метрика загружается только после явного выбора
  посетителя «Разрешить аналитику»; отказ сохраняется локально и не загружает
  `mc.yandex.ru`.
- Код подключения покрыт тестами. Цель «Переход на Яндекс Маркет» создана в
  Метрике с точным идентификатором `market_click`; тестовый сигнал endpoint
  принял 30 июля 2026 года. Вебвизор и карта кликов намеренно выключены;
  событие содержит только технические идентификаторы карточки, страницы и VID,
  без пользовательских данных.
- После применения portable growth playbook добавлена единая обезличенная цель
  полезного результата `result_completed`. Она возникает только после явного
  успешного расчёта в одном из семи калькуляторов либо после явного выбора
  модели и механизма с непустым результатом подбора. Загрузка страницы и
  повторный React-рендер целью не считаются.
- В `result_completed` допускаются только контролируемые идентификаторы
  инструмента и типа результата, безопасный путь страницы и ограниченное
  количество найденных вариантов. Модель телевизора, механизм, параметры
  стены, числа из калькулятора и текст поиска не передаются. До согласия
  посетителя событие не попадает в Метрику, потому что её обработчик не
  установлен.
- Добавлена промежуточная цель `mount_detail_click` для перехода от результата
  к подробной проверке кронштейна. В неё передаётся только закрытый тип места
  ссылки: короткий список или полный список совместимости. Модель телевизора,
  кронштейн, URL, механизм и пользовательские параметры не передаются.
- Код целей покрыт тестами. Отдельный OAuth приложения
  `KREPI TV · Метрика API` с минимальными правами `metrika:read` и
  `metrika:write` использован для идемпотентного создания недостающих целей;
  ранее существовавший токен не изменялся. Повторный authoritative GET
  Management API 31 июля подтвердил все три цели: `market_click` (goal ID
  `590833702`), `result_completed` (goal ID `590998776`) и
  `mount_detail_click` (goal ID `590998778`). Наличие цели означает только
  готовность измерения, а не достижение конверсии.
- Идемпотентный менеджер `scripts/analytics/manage-metrika-goals.mjs` проверяет
  ровно одно условие `exact`, запрещает дубли и конфликт имён, не повторяет POST
  вслепую после сетевого таймаута и повторно сверяет список после создания.
  Старый локальный OAuth имеет только `metrika:read` и не изменялся. Новый
  отдельный токен хранится только в `.private`, имеет ровно два необходимых
  scope и успешно прошёл повторную readback-проверку после создания целей.

- Интерфейс партнёрской статистики Маркета за 1–31 июля показывает 1 переход
  по Onkron TM5-BW, 0 заказов, 0 ₽ награды и 0% отмен. Этот переход не связан
  с подтверждённой органической сессией и не считается доходом.

## Активация и проверка

1. Исключить прямой визит с `metrika-test=1` и тестовый `reachGoal` из
   продуктовых отчётов.
2. Не считать текущий товарный VID достаточной атрибуцией страницы: один и тот
   же оффер переиспользуется на карточках моделей, кронштейнов и SEO-хабах.
3. До первого реального трафика выпускать VID на уровне
   `landing × offer × rank`, сохраняя приватное соответствие размещению.
4. Получать read-only `GET /orders` ежедневно и сохранять только технические
   поля заказа: хеш идентификатора, даты создания и изменения, статус, VID и
   `payment`. Исходные снимки и OAuth не публиковать.

Проверка конфигурации без изменений:

```bash
YANDEX_ANALYTICS_CREDENTIALS=/absolute/path/yandex-oauth.json \
  npm run analytics:goals:check
```

Применение разрешено только токеном с `metrika:write` и выполняется отдельной
командой `npm run analytics:goals:apply`. При неизвестном исходе POST менеджер
сначала перечитывает authoritative list и не создаёт возможный дубль.

Официальная документация:

- <https://yandex.ru/support/metrica/ru/general/creating-counter>
- <https://yandex.ru/support/metrica/ru/objects/reachgoal>

## Воронка

Органический вход считается только по источнику поисковой системы. Исходящий
клик `market_click` наблюдается только у посетителей, разрешивших Метрику;
поэтому его нельзя без показателя покрытия делить на все заказы API. Заказы и
выплаты берутся из партнёрского API по уникальному VID размещения.

```text
organic_sessions → result_completed → mount_detail_click → market_click → created_order
                 → APPROVED order → payment
```

На справочнике винтов успешный поиск отправляет тот же consent-gated
`result_completed` с закрытыми значениями `tool_id=screw_lookup` и
`result_kind=mount_screws_found`. В событие попадает только ограниченное число
результатов; строка поиска и модель телевизора не передаются.

Показы, прямые и тестовые визиты, клики без заказа, `NEW`, `ON_HOLD`,
`CANCELLED`, обещанная награда и сумма корзины не являются подтверждённым
вознаграждением.

## Обязательные отчёты

- Ежедневный приватный реестр: новые и изменившиеся заказы, возраст незакрытых
  статусов и сумма `payment` только для `APPROVED`.
- Недельная зрелая когорта по `landing × placement × VID`: органические
  сессии, наблюдаемые клики, созданные и финальные заказы, доля подтверждения,
  средний `APPROVED payment` и подтверждённый доход на органическую сессию.
- Месячный goal ledger: сумма `payment` заказов, ставших `APPROVED` в месяце,
  против цели 100 000 ₽. Текущее подтверждённое значение — **0 ₽**.
- Заказы текущей недели не делятся на клики той же недели: учитываются
  семидневная атрибуция, получение заказа и возвратное окно.

## Интерфейс измерения после SEO-волны 6

- Запрос согласия Метрики расположен в потоке сразу после шапки и не перекрывает
  кнопки, каталог или результаты проверки на мобильном экране.
- Семь калькуляторов отправляют ровно одно `result_completed` после каждого
  успешного явного запуска. Мастер `/podbor/` защищён от повторов StrictMode и
  устаревшего результата при переключении механизма.
- Внешнему CTA на SEO-хабах и карточках телевизоров предшествует внутренняя
  ссылка «Проверить VESA и нагрузку». Она ведёт только на существующую карточку
  точного кронштейна, отправляет только
  `{placement: "compatibility_result"}` и не создаёт новый индексируемый URL.
- В `/podbor/` три полностью проверенных результата показаны сразу. Остальные
  варианты спрятаны под явным раскрытием и сгруппированы по брендам; все
  внутренние ссылки ведут на существующую карточку точного кронштейна.
- Для `/kronshteyny-onkron/` порядок воронки закреплён тестом:
  сравнение пяти моделей → два свежих предложения → поиск точной модели ТВ.
- В `/podbor/` наличие свежего точного оффера используется только как
  tie-break после уровня совместимости и технического score. Поэтому коммерция
  не может вытеснить более подходящий кронштейн. Аудит 719 мест top-3 увеличил
  покрытие свежими офферами с 50,8% до 80,3% без потери качества; публикация и
  наличие оффера сами по себе не считаются переходом, заказом или доходом.

## Закрытие разрывов измерения — 31 июля

- SEO-хабы теперь используют тот же `MountDetailLink`, что мастер и карточки
  моделей; переход «Проверить VESA и нагрузку» больше не обходит
  `mount_detail_click`.
- `emitAffiliateClick` перехватывает ошибку browser event API и возвращает
  `false`: недоступность аналитики не должна рисковать переходом пользователя
  на Маркет.
- Интеграционный тест consent-gate проверяет всю локальную последовательность
  `result_completed → mount_detail_click → market_click`: до согласия ни одно
  событие не воспроизводится, после согласия порядок и безопасные payload
  точны.
- Полный release gate прошёл 230 тестов, русскоязычный UI, 141 URL sitemap,
  80 моделей, 23 кронштейна и 1 405 verified-fit связей. Это доказывает готовый
  код измерения, но не наличие двух целей в аккаунте Метрики.
- Source commit `b0855dfba129774aca86e0febd7c0518348155ea` опубликован успешным
  GitHub Pages run `30616121511`. Production использует
  `/assets/main-NG3mXria.js`; его SHA-256 побайтно совпал с локальным релизом:
  `ce50eeabb5d08e9f01876eb4e39a79f3cfb42a1c8f1502d31b8883a44814c384`.
- Изолированный production DOM ONKRON-хаба содержит три внутренние ссылки с
  `data-mount-detail-placement="compatibility_result"` и три живых перехода на
  Маркет. Старого длинного дисклеймера и runtime `TypeError`/`ReferenceError`
  нет; главная и хаб отвечают 200 с TLS verify 0.
