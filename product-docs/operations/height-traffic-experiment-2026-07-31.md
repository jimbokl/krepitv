# KREPI TV — трафиковый эксперимент на калькуляторе высоты

Дата решения: 31 июля 2026 года.

Статус: локальный release gate пройден; production проверяется отдельно по
фактически опубликованному commit SHA.

## Почему улучшен один существующий canonical

Строгий Wordstat-срез по России дал отдельные exact-частоты:

| Запрос | Частота |
|---|---:|
| `на какой высоте вешать телевизор` | 8 251 |
| `высота телевизора на стене от пола` | 2 627 |
| `высота телевизора на стене в спальне` | 1 576 |
| `на какой высоте вешать телевизор 55 дюймов` | 411 |
| `высота телевизора на стене на кухне` | 217 |

Формулировки пересекаются, поэтому частоты не складываются и не объявляются
уникальной аудиторией. Все они описывают один job; улучшена существующая
страница `/na-kakoy-vysote-veshat-televizor/`, новые спальня/кухня URL не
созданы. Исходные данные находятся в
`data/research/problem-intent-demand-2026-07-31.json`.

## Собственная полезность страницы

После расчёта пользователь получает не только три числа, но и доступную
масштабированную SVG-схему: верхний край, центр и нижний край относительно
чистого пола. Противоречивые и неполные значения блокируют схему. Результат не
содержит цены, SKU или ссылки на Маркет.

Следующий самостоятельный job связан внутренними ссылками:

1. перенести центр экрана в контрольную линию пластины через монтажную карту;
2. проверить точную модель телевизора и совместимый кронштейн.

Это сохраняет цепочку `поисковая боль → собственный расчёт → проверка точной
модели → технически совместимый товар`, не превращая калькулятор в прокладку
партнёрской программы.

## Измерительный baseline

До релиза Google подтвердил 8 из 142 canonical в индексе. За финальное окно
02–29 июля — 0 показов и 0 кликов. Яндекс Вебмастер ещё не загрузил зрелые
данные по хосту; это `not_matured`, а не ноль. Метрика показывает 0
органических пользователей. Подтверждённый результат партнёрки — 0 заказов и
0 ₽ `APPROVED payment`.

Лестница результата эксперимента:

`индексация → 10 релевантных показов → органический клик → result_completed →
detail_click → market_click → заказ → APPROVED payment`.

До появления данных страница повторно не переписывается, а соседние
canonical под формулировки спальни и кухни не создаются.

## Локальный release gate

- полный Rust/WASM/web build прошёл; 96 web, 22 sitegen, 74 affiliate и 41
  analytics-проверка зелёные;
- sitemap сохранил ровно 142 indexable canonical и максимальную глубину 2;
- mobile E2E 390×844 получил 148,5 / 114,2 / 80 см, без overflow и без ссылки
  на Маркет в результате;
- desktop E2E 1440×1000 подтвердил читаемость трёх линий и отсутствие
  пересечений подписей;
- security, static, affiliate и design-evidence harness-аудиты прошли весь
  репозиторий и production-артефакт; визуальная оценка снимков выполнена
  отдельно;
- token `YMReferral` удалён из поискового description главной, но сохранён в
  отдельном verification meta только на корневом canonical;
- тест размещений исправлен: постоянный manifest проверяется независимо от
  динамического public subset, поэтому исчезновение товара безопасно снимает
  CTA и больше не ломает выпуск остальных проверенных офферов.

Снимки проверки находятся в
`product-docs/design-qa/2026-07-31-height-plan/`.

HTTP 202 от IndexNow будет считаться только принятым уведомлением. Показы,
клики, заказы и доход этим релизом не заявляются.
