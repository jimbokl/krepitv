# Визуальный спринт «Полный монтажный комплект»

**Дата:** 25 августа 2026 года  
**Поверхность:** существующий canonical `/podbor/` и его печатный результат  
**Фреймворк:** React + Vite + Tailwind CSS; Rust/WASM остаётся единственным источником расчётов

## Цель

Сделать мастер полного монтажного комплекта визуально самостоятельным продуктом: пользователь с телефоном и рулеткой должен без напряжения пройти шесть шагов, понять границы точности и передать монтажнику один читаемый «монтажный паспорт». Редизайн не меняет доменную математику, правила `verified` / `needs-check` / `blocked`, каталог, партнёрскую политику или индексируемые URL.

## Выбранное направление

1. **Продукт и аудитория.** Владелец конкретной модели телевизора, который монтирует её сам или готовит проверяемое ТЗ мастеру.
2. **Тон.** Редакционный, инженерный, спокойный: «измерительный прибор, которому понятны границы точности».
3. **Композиция.** На широком экране — асимметричная редакционная сетка с вертикальным прогрессом; на телефоне — один вопрос на экран, крупные цели касания и короткая сводка выбранного ТВ.
4. **Типографика.** Roboto Condensed для выразительных русских заголовков, IBM Plex Sans для чтения, IBM Plex Mono и табличные цифры только для моделей, размеров и статусов.
5. **Цвет.** Тёплая бумага, графитовый текст, строительный оранжевый только для главного действия, спокойный зелёный только для доказанного, технический синий только для фактического контекста, янтарный/красный только для проверки и остановки.
6. **Движение.** Короткие переходы состояния, которые объясняют выбор или продвижение; `prefers-reduced-motion` отключает их. Декоративной анимации нет.
7. **Фирменный элемент.** Линейка-координатор: деления и контрольная линия связывают прогресс, поля размеров и итоговую карту высот. Это не шкала точек сверления.

## Экран мастера

### Оболочка

- Сохраняется один маршрут и текущий шестишаговый reducer.
- Desktop: левая колонка шириной около 18rem содержит бренд, обещание продукта и вертикальную шкалу шагов; основной вопрос занимает остальную ширину.
- Mobile/tablet: бренд и обещание компактны; прогресс — горизонтальная шкала без длинных подписей; основной вопрос начинается в первом видимом экране после баннера согласия.
- Верх и низ оболочки получают тонкую координатную шкалу через фоновый CSS-паттерн. Она `aria-hidden`, не имитирует измерение и не содержит числовых отметок.

### Шаги

- На каждом шаге остаётся один главный вопрос и одно главное действие.
- Select бренда и модели остаются нативными выпадающими списками, как ранее потребовал владелец продукта.
- Выбор стены и механизма — единая группа строк/плиток с большим кликабельным полем, реальным radio-input и явным selected-state.
- Выбранная модель показывается компактной технической полосой: модель, диагональ, VESA, масса и дата проверки, но только когда эти значения доказаны.
- Кнопки «Назад» и «Продолжить» не прыгают между шагами; на телефоне главное действие занимает всю ширину.
- Фокус и прокрутка после перехода остаются на заголовке нового шага; первоначальный select не получает `autofocus`.

### Предпросмотр ценности

На первом шаге desktop показывает компактный список результата: совместимость, винты, стеновой крепёж, высота, кабели и чек-лист. Это объясняет продукт, но не подставляет фиктивные значения и не создаёт вторую форму. На mobile этот блок свёрнут в `details` после главного действия.

## Монтажный паспорт

- Заголовок результата сначала сообщает общий статус и точную пару «модель + кронштейн».
- Печать остаётся доступна сразу. Прямая ссылка Маркета появляется только при `market_eligible`, `compatibility.status === "verified"` и валидном свежем offer.
- Семь существующих секций сохраняются в том же порядке и остаются независимыми.
- На desktop секции образуют читаемый документ: основной поток слева, компактная статусная навигация справа; на mobile это один поток.
- Статус — не декоративный бейдж: рядом с заголовком секции есть иконка, текст и цвет, но смысл не зависит только от цвета.
- Карта высот выделяет одну доказанную контрольную линию крупными табличными цифрами. Она явно подписана как линия настенной площадки, не точка сверления.
- Таблицы остаются таблицами, списки — списками; длинные подробности и источники раскрываются прогрессивно, без каскада карточек внутри карточек.
- Печатная версия удаляет навигацию, партнёрские блоки и декоративный фон, сохраняет входные данные, статусы, предупреждения и источники.

## Компонентная граница

- `GuidedSelectionPage.jsx` владеет компоновкой, переходами и общей сводкой.
- `KitStepRail.jsx` владеет только прогрессом.
- `KitOutcomePreview.jsx` — новый статический SSR-компонент, объясняющий семь результатов без данных пользователя.
- `InstallationKitResult.jsx` владеет шапкой монтажного паспорта и компоновкой секций.
- `KitSection.jsx` владеет единым статусным заголовком, предупреждениями и disclosure.
- Доменные панели (`CompatibilityPanel`, `ScrewPanel`, `WallFixingPanel`, `PlacementPanel`, `CablePanel`, `ToolsPanel`, `PrintableChecklist`) продолжают получать только свою секцию плана.
- `styles.css` и Tailwind tokens задают измерительную шкалу, tabular numerals, состояния и print-safe поверхности. Новых UI-фреймворков и runtime-зависимостей нет.

## Доступность и производительность

- Контраст текста и интерактивных состояний не ниже WCAG AA.
- Минимальная цель касания — 44×44 CSS px; primary-кнопка на mobile — не ниже 52 px.
- Radio/select сохраняют нативную семантику; декоративные изображения и шкалы скрыты от accessibility tree.
- Visible focus есть у каждого интерактивного элемента; клавиатурный путь повторяет визуальный.
- Весь публичный текст — русский.
- Редизайн не добавляет внешние JS, webfont-запросы, тяжёлые библиотеки или новый hydration boundary.
- CLS не создаётся: размеры будущих изображений фиксированы, но в первом релизе используются только существующие иконки и кодовые технические диаграммы. Растровые mockup-референсы не загружаются пользователю.

## Ограничения из дизайн-отчёта

В этот спринт входят mobile-first, progressive disclosure, крупные цели касания, табличные цифры и монтажный паспорт. Не входят dark mode, OCR шильдика, haptic API и отдельный Room Visualizer: они требуют собственной проверки спроса и поведения. Не используются цены или логотип Маркета. Не публикуются точки сверления, диаметр бура или точный анкер без полной геометрии и evidence-контракта.

## Проверка готовности

- SSR-тест фиксирует ключевые visual-contract hooks, русские подписи и неизменные fail-closed условия.
- Targeted web tests проходят отдельно до общего build.
- Browser QA проходит полный путь на 390, 768 и 1440 CSS px: brand → model → wall → mechanism → mount → placement → result.
- Нет горизонтального overflow, перекрытия текста, потери фокуса или недоступного действия.
- `design-qa.md` содержит сравнение reference/implementation и строку `final result: passed` после исправления P0/P1/P2.
- `npm run build` и `node scripts/verify.mjs` проходят; sitemap остаётся на 299 URL.
- Production artifact публикуется только после успешного Pages workflow и побайтовой проверки `/podbor/`.
