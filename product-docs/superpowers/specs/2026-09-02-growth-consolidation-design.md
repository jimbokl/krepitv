# Закрепление органического роста и измеримой воронки

## Контекст

На 2 сентября 2026 года Google дал среднесрочный рост: 3 114 показов и 48 кликов за 19 августа — 1 сентября против 1 598 показов и 36 кликов за предыдущие 14 дней. Последняя неделя при этом снизилась до 1 048 показов и 16 кликов. Метрика впервые зафиксировала 18 органических пользователей за полную неделю, но не зафиксировала ни одного органического перехода к карточке кронштейна или на Яндекс Маркет. Яндекс держит только 38 страниц в поиске при 299 URL sitemap и показывает постоянное появление и удаление части страниц.

## Цель спринта

Сделать существующий органический трафик измеримым и направить посетителя от самостоятельного результата к подтверждённому подбору кронштейна, одновременно уменьшив риск некачественной индексации. Новые индексируемые URL в этом спринте не создаются.

## Продуктовый контракт

Для владельца телевизора, который пришёл решить конкретную проблему или проверить параметр, KREPI TV сначала выдаёт самостоятельный проверяемый результат, затем предлагает перейти к подбору совместимого кронштейна по точной модели. Коммерческая ссылка появляется только после технической проверки совместимости.

Первый полезный результат: пользователь получил готовый расчёт, диагностический маршрут или подтверждённую характеристику.

Следующая работа: пользователь начал точный подбор кронштейна, открыл карточку проверенного крепления и при необходимости перешёл на Яндекс Маркет.

## Архитектура измерения

Воронка становится шестиступенчатой:

```text
organic landing
→ tool_usage
→ result_completed
→ selection_start
→ mount_detail_click
→ market_click
→ APPROVED order
```

`result_completed` измеряет активацию инструмента, поэтому отправляется не более одного раза для пары `tool_id × source_path` за жизненный цикл страницы. Повторные перерасчёты остаются функциональными, но не раздувают цель активации.

`selection_start` отправляется только при явном переходе пользователя из полезного результата в `/podbor/`. Событие содержит только контролируемое место CTA и безопасный pathname. Оно не содержит модель, пользовательский ввод, параметры расчёта или полный URL.

Отчёт Метрики должен сохранять агрегированные totals даже тогда, когда API не поддерживает измерения `goal paramsLevel`. Детальная разбивка по инструментам в такой ситуации получает состояние `unavailable`, а не ломает весь отчёт и не превращается в выдуманный ноль.

## SEO и переход к следующей работе

Массовая публикация заморожена. Улучшаются только существующие страницы с доказанными показами:

- `/skolko-elektroenergii-potreblyaet-televizor/` — диагностировать резкое падение показов, укрепить прямой ответ и внутренние ссылки;
- `/kak-otklyuchit-subtitry-na-televizore/` — улучшить соответствие высокочастотным формулировкам без расширения интента;
- `/kak-otklyuchit-golos-na-televizore/` — сохранить растущий кластер и повысить CTR;
- `/tablica-vesa-televizorov/` — усилить переход от справочного ответа к точному поиску модели и подбору;
- страницы моделей Xiaomi 2026 — сохранить технические паспорта и контекстные внутренние переходы без создания дополнительных моделей.

Общий `MountFunnelNextStep` остаётся после самостоятельного результата, но получает измеряемый переход и контекстный текст, объясняющий, что произойдёт в подборе. Прямой affiliate CTA в справочных инструментах не добавляется.

## Индексация Яндекса

Семь исключённых URL и последние события `REMOVED_FROM_SEARCH` рассматриваются как качество/каноникализация, а не как повод повторно отправлять весь sitemap. Выпуск не создаёт новые URL и не меняет canonical. Для страниц, изменённых по доказанному спросу, обновляется `updated_at` и `lastmod` только при содержательном изменении. После релиза в IndexNow отправляются только изменённые canonical.

## Ограничения

- Весь публичный интерфейс — только на русском языке.
- Хостинг остаётся GitHub Pages; Cloud.ru и платная инфраструктура запрещены.
- Прямые ссылки ведут на `market.yandex.ru`; редиректы, клоакинг и цены запрещены.
- Сайт остаётся полезным при удалении всех affiliate CTA.
- Никакие токены, идентификаторы аккаунтов, заказов, placement/VID/CLID или персональные данные не попадают в git, HTML и публичные отчёты.
- Критический результат должен присутствовать в SSR или сохраняться без JavaScript там, где интерактивность не обязательна.
- Новые зависимости не добавляются.

## Проверка результата

Спринт завершён только когда:

1. тест доказывает однократную отправку `result_completed` для одной страницы и инструмента;
2. `selection_start` проходит безопасную валидацию, отправляется из общего CTA и создан как точная action-goal в Метрике;
3. отчёт Метрики возвращает totals при неподдерживаемой детализации goal parameters;
4. изменённые SEO-страницы сохраняют самостоятельный SSR, источники, breadcrumbs, canonical и внутреннюю следующую работу;
5. sitemap остаётся равен множеству indexable canonical и содержит 299 URL;
6. полный `npm run build:release`, SEO/affiliate/security/design gates и production browser smoke проходят;
7. production отвечает по HTTPS, HTTP перенаправляется на HTTPS, а опубликованные изменённые файлы совпадают с проверенным artifact.
