# Финальный SEO-спринт перед месячной выдержкой

## Цель

Усилить существующие 288 индексируемых URL KREPI TV без массовой генерации,
фиктивной региональности и неподтверждённых коммерческих заявлений, затем
заморозить продуктовые изменения на месяц для накопления чистых поисковых
данных.

## Принятые решения

1. На каждой индексируемой странице, кроме главной, появляется видимая
   навигационная цепочка. Её пункты и порядок побайтно соответствуют
   `BreadcrumbList` в JSON-LD.
2. Создаётся один самостоятельный URL `/spravochnik/`. Он группирует все
   индексируемые руководства по реальной пользовательской задаче и становится
   родителем для их breadcrumbs. Это не новая контентная матрица.
3. Пятьдесят материалов с `guide` получают компактное содержание с обычными
   `<a href="#...">` и стабильными идентификаторами реальных разделов.
4. Для каждой паспортной модели телевизора и каждого кронштейна генератор
   создаёт отдельную техническую SVG-схему из проверенных характеристик.
   Страница показывает её через обычный `<img>`, `Product.image` указывает на
   тот же URL, а sitemap перечисляет изображение рядом с каноникалом.
5. Главная получает единую сущность `Organization` с настоящими полями KREPI
   TV, crawlable SVG-логотипом, `alternateName` и `og:site_name`. Адрес,
   телефон, отзывы, рейтинг и `LocalBusiness` не выдумываются.
6. Регион сайта не привязывается к Москве или отдельным городам. KREPI TV
   остаётся общероссийским информационным онлайн-сервисом.

## Архитектура

- Rust sitegen остаётся источником истины для маршрутов, SSR, JSON-LD,
  breadcrumbs, sitemap и технических SVG.
- React получает общий компонент `Breadcrumbs` и повторяет ту же иерархию
  после гидратации.
- `/spravochnik/` строится из существующего `data/seo_pages.json`; новая
  ручная копия 105 названий не создаётся.
- Технические изображения содержат только модель, VESA, массу или параметры
  кронштейна. Они не изображают физический тест и не маскируются под фото.
- Существующие canonical, direct Market links, цены, приватные данные и
  аналитический контракт не меняются.

## UX

- Breadcrumbs занимают одну строку, допускают перенос, используют текущие
  mono/action-токены и имеют заметный `focus-visible`.
- Справочник показывает сначала поиск задач и основные инструменты, затем
  тематические группы под native `<details>`, чтобы не создавать простыню.
- Содержание руководства содержит только реальные секции: мастер/таблица,
  граница остановки, официальные источники и связанные материалы.
- SVG-схема имеет осмысленный `alt`, подпись и фиксированные размеры, чтобы не
  вызывать layout shift.

## Проверка

- TDD-контракты сначала падают на отсутствии видимых breadcrumbs, хаба,
  содержания, изображений и Organization.
- Rust и web-тесты проверяют SSR/React-паритет и отсутствие выдуманных данных.
- Полный `npm run build` остаётся единственным release gate.
- После публикации проверяются HTTPS, sitemap, representative HTML/SVG и
  побайтовое совпадение production с `docs/`.
- IndexNow receipt считается только уведомлением, не индексацией.

## Месячная пауза

После успешного production-релиза ежедневный SEO-мониторинг приостанавливается
до 10 сентября 2026 года. В паузе не создаются URL и не переписываются
страницы. После даты выдержки собирается одно сравнение Google, Яндекса и
Метрики по полным окнам; никакие показы или клики не называются уникальными
посетителями.
